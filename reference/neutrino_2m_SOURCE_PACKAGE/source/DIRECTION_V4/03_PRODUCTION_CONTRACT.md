Read all six supplied files and relevant HyperFrames skills. Check `ffmpeg`, `ffprobe`, directory and source. Create a checkpoint or git commit; never overwrite past experiment. Write a concise list of factual source/claims and constraints. No prolonged preflight.

### 2. Original world invention + visual preproduction — VISIBLE ART gate
Read `02_VISUAL_MOTION_GRAMMAR.md`. ### 3. Director's editorial animatic — TIMING gate
Create 25–35 *meaningful* visual beats (the CSV is a suggestion, not a forced shot count). Each beat has a narration alignment, main visible event, actual story consequence, frame change, camera, secondary activity and attention handoff. Use voiceover-based timing if audio exists. Make a fast watchable rough **120-second animatic** with compositions and appropriate sound. If a cold viewer cannot explain what changed from one section to the next, repair staging/causality here instead of polishing weak art.

### 4. 12-second PERFORMANCE PROOF — motion gate
Use the actual selected artwork, create articulated pose-driven movement, multi-plane parallax, meaningful object interaction, attention changes and a real transformation for first 12 seconds. If it consists of images sliding/fading/zooming, it FAILS regardless of rendering validity. Do no more than two targeted corrections before explaining the blocker. Save `proof_12s.mp4`.

### 5. Full production — 120 seconds without creative backsliding
Once the proofs are technically and visually sound, implement the rest with the same art quality. Work in ~15–25-second *connected* groups while keeping the full script's continuity and sound sync. All animation seekable/deterministic; no random unseeded behavior. Use original SVG layered assets, GSAP timelines with proper HyperFrames registration; browser render works from arbitrary timeline positions. Do not substitute static narration slides, generic symbols, or repeat one scene under different captions.

### 6. Watch actual film, target repairs, render final
Run installed HyperFrames lint/check/snapshots and `ffprobe` (real duration, dimensions, fps, audio stream). Protect finished quality rather than declaring success from empty validators.

Report output path, cost evidence (subscription usage cannot be converted to API dollars), actual technical defects, artistic shortcomings, audio status, proof renders and the full MP4.

## Guardrails against the failure we've experienced
- 'I imagined it' is NOT equivalent to visible artwork. Generate and inspect real full-size hero frames.
- 'I wrote 20 pages of direction' is NOT equivalent to a moving shot. Make the 12-second proof immediately after hero frames and rough animatic.
- 'The CLI rendered' is NOT proof of cinematic quality. Watch normal-speed motion and inspect dense samples.
- 'Many elements move' is NOT a creative event. They must cause or support a meaningful visual transformation.
- 'Cinematic' does not mean slow. Visually meaningful changes should occur frequently, matched to the actual narrated information. No opening logo/title hold.
- A flawed idea needs a creative redesign, not cosmetic polish or more decorative motion.
- No late directorial improvisation by a cheap executor; the important art, stage, and timing decisions must be explicit and approved within the artifacts.
- The two-minute video must have an actual explanation and visual learning payoff, not a plotless space movie.

# THE BETTER ONE — PERMANENT EPISODE PRODUCTION OPERATING STANDARD V1.0
**Scope:** E01 and every future 8–13-minute episode, or 20-minute episode if editorially earned. **Authority:** repeatable workflow; not a claim the P06 engine has implemented or passed all gates.
**Binding sources:** THE_BETTER_ONE_MASTER_CHANNEL_BIBLE_v1.md; FIRST_FILM_PRODUCTION_MASTER.md; inputs/EXPERIENCE_DIRECTOR_V1.md; ART_MOTION_AND_HYBRID_QUALITY_GATES.md; P06_13S_PERFORMANCE_SYSTEM_IMPLEMENTATION_DIRECTIVE.md; PRODUCTION_QUALITY_GATE_REGISTRY.json; actual source schemas and runtime producers. Do not duplicate or replace their underlying visual/artistic rules with a superficial summary.

## 0. One-sentence definition of success
Produce an original, exceptionally entertaining Better One episode whose actual final audiovisual footage communicates a defensible surprising idea, preserves its character's emotion/identity, contains beautiful approved artwork and expressive motion, and survives real human/editorial + technical review. **Tests and pretty frames are evidence, not the product.** Accepted film seconds and genuine viewer clarity are the leading production outputs; actual retention is measured only after release.

### Authority order and conflict handling
1. Latest explicit USER-approved creative decisions for this episode; never convert GPT proposals or machine output to a human approval.
2. Channel Bible for editorial identity, quality, ethics, packaging, audience and research. Latest explicit user correction supersedes an earlier conflicting local choice; capture the reason/affected IDs in the decision register.
3. Approved screenplay, Experience Director, artwork designs and actual human approval receipts (immutable version hashes).
4. Production Operating Standard for stage order, evidence, restart and handoffs.
5. P06 and actual implemented engine schemas/consumers for technical feasibility. Engineering cannot overrule the script by silently deleting an action; it must issue a typed support/refusal and request a creative decision.
6. Historical V0.1–V0.3 samples, older scene-specific tests and defaults are reference only.

**Conflict example:** old README/CLAUDE/HANDOFF say “8–10 seconds”; the selected E01 qualification is **13.000 seconds = 780 frames at 60fps**, not a mandatory episode-wide shot length. Do not impose 13 seconds on storytelling. Every later episode picks a meaningful contiguous film interval of appropriate tested length. Long film runtime is decided by editorial value, not engine convenience.

### Explicit status vocabulary
- PROPOSED: generated or researched; no human sign-off.
- EDITORIALLY_APPROVED: exact screenplay/direction revision and scope signed off by user; not proof of renderability.
- ENGINE_PREFLIGHT_SUPPORTED: real source-specific action and state obligations accepted by current implemented engine; conditional on correct real assets.
- NEEDS_ART / NEEDS_HOST / NEEDS_AUDIO / NEEDS_CODE / NEEDS_HUMAN: explicit missing input or producer, with owner and remediation.
- POSTART_FEASIBLE: actual approved image geometry/rig has passed required per-frame checks.
- TECHNICALLY_RENDERED: correctly rendered frames + relevant QA; does not imply artistic quality.
- HUMAN_VISUALLY_APPROVED: user reviewed native actual moving-picture footage with final sound and approved the exact SHA.
- PUBLISHABLE: all required editorial/legal/technical/rights checks and full film approval completed.
Never equate test PASS, document consistency, or diagnostic art with HUMAN_VISUALLY_APPROVED.

## 1. Full reusable pipeline — the actual dependency graph

Episode candidate / topic research and viewer promise
  → F/R/M/H/X evidence ledger + math/model card + rival explanations
  → 15-field Value Blueprint and proposed credible ending + counterexamples
  → Title/thumbnail promise candidates and first 10-second payoff
  → Full screenplay + distinct characters, relationships, jokes, reveal order and emotional arc
  → Scratch performances and audio-first rough visual animatic; adjust dialogue/pacing
  → User approves creative intent and chosen film/clip interval
  → Experience Director V1 full 12-part per-shot contracts and all timed acting/interaction/audio routes
  → Actual v1.1.0 CREATIVE_PACKET + hashed linked source files
  → P06 creative preflight and action/rig/art demand closure (NO silent fallback)
  → Approved art-design requests, current F01–F80 skill and native witnesses verified
  → Genuine GPT-generated character/environment masters, source-attached part/view/cel families, human approvals
  → Real-art landmark measurement, rig/state fitting, every required frame feasibility
  → Neutrino 2D animation + separate genuine Blender host + source-model-linked graphics
  → Frame-accurate composition + recorded sound/music/SFX + full MP4 verification
  → Continuous human review and defect repair at earliest producing cause
  → Accepted real film clip logged with asset/code/source SHA; repeat approved contiguous intervals
  → 90–120s contiguous hybrid proof; complete film; package/title/rights/full release checks

Every arrow is a **contract with input files, version hashes, actual consumer and refusal behavior**. An eloquent narrative or lengthy custom source pack is NOT a substitute for any arrow being executed. Art generated out of stage order must remain unapproved exploration.

### Three parallel workstreams, one master story authority
CREATIVE = GPT + user: model, plot, full film, acting/cinematography, truth, art requirements, approval.
TECHNICAL = Claude + current source: P06 operators, real pre/post-art validation, rig fit, render, A/V, evidence, technical repair.
ART = GPT manual current F01–F80 + user, and approved Blender artist/engineering for host: own actual editable asset sources and consistency.
Parallelize independent work; do NOT fabricate dependent inputs (approved directions, final image states, host model or recorded dialogue) just to keep a worker busy.

## 2. Mandatory stage-by-stage process and pass conditions

### S0 — Choose the episode and what the audience gets
Owner: GPT researcher/showrunner, user approval.
Input: Channel Bible (formats R/U/T/C/H/N), research candidate, viewer promise.
Output: EPISODE_BRIEF.md: episode ID, candidate title/thumbnail, target audience, stakes, protagonist, emotional question, "click / watch / return" reasons, one-sentence hypothetical or documented truth mode, why this is an episode not an anecdote.
Gate: real contradiction and viewer value can be stated in child-simple language; three alternate viable pitches compared. Do not claim a viral guarantee or invent an audience test.

### S1 — Establish economic/causal truth BEFORE full dialogue
Input: primary research, sources, model assumptions and counterevidence.
Outputs: SOURCE_LEDGER.csv; MODEL_CARD.json (parameters, units, truth flags, resource constraints, day parts, demand response, cash vs accounting, formulas, scenarios, sensitivity/counterexamples); 15_FIELD_VALUE_BLUEPRINT.md; ENDING_PROOF.md; DECISION_REGISTER.md.
Gate: actual source URLs/references and dates; F=fact, R=reconstruction, M=declared model, H=hypothesis, X=fiction; no source for an invented number; reproducible computation; competing solutions survive honest pressure tests. Distinguish financial possibility from an actual rescued restaurant.
E01 example: 4-zone/1,200 equivalent daily grill-slot-minutes is a FICTIONAL hypothesis with day-part schedule. Middle menu redesign alone is NOT guaranteed financial rescue. Do not auto-select a winning strategy because it makes a better graph.

### S2 — Write a MOVIE first, then time it
Input: approved central value + package and constraints.
Outputs: complete screenplay version; scene cards covering full 8–13min, possibly 20min if earned; dialogue/character performance roster; clues/plant/payoff ledger; host-personality continuity; transition/decode plan; rough audio/animatic project.
Gate: character has agency and distinct identity; relationship chemistry; real early click-promise fulfillment (target within first 10 seconds); specific causal surprise; meaningful changes each beat; host fallible; natural dialogue; no unnecessary business-lecture exposition. The opening must work as entertainment before molecular geometry is specified.
**Perform first:** rough voices at unconstrained natural speed, then audio-first animatic with temporary drawings and 2D/3D blocks labeled PREVIS ONLY; correct timing based on actual playback. Scratch can be rough and free; it is NOT final voice approval.
**No premature 13-second restriction:** choose a complete 20–35s opening when earned, then select a contiguous 13s window for E01's first technical qualification.

### S3 — Experience Director and creative version lock
Input: screenplay with actual revised audio timing + approved storyboard/blocking.
Output: EXPERIENCE_DIRECTOR_vN.md and a shot table for every scene with 12 mandatory fields exactly as inputs/EXPERIENCE_DIRECTOR_V1.md defines; STORYBOARD/ANIMATIC; SHOT_TIMELINE.csv; ACTION_GRAPH.json; CONTINUITY_STATE.json; AUDIO_CUE_PLAN.json; ART_REQUIREMENTS.md; MEDIA_ROUTE_MAP.json; EDITORIAL_APPROVAL_REQUEST.md.
At minimum every consequential action states: shot ID, absolute [start,end) frame interval, direction/action ID, actors and object ownership, target/world location/space, physical intention, before/after pose/contact/expression/view, eye/hand/mouth demand, preparation/hold/recovery, exact sound intent, camera, visibility/occlusion, expected on-screen effect and continuity into next shot.
Camera changes must be motivated. Animated film must keep more than one action alive when the story requires it; no single-action puppet tableaux.
Director approves **performance and framing, not fictional bone lengths**: actual painted art determines pivots and permissible deformation. Multi-actor verbs produce synchronized but independently controlled performers.
Gate: user reviews the actual scene concept, dialogue/performance and rough animatic; all 12 contract fields covered; action IDs stable; times synchronized to actual performed takes; scenes hand off states, not just dissolve. Clear explicit human decision before final art.

### S4 — Actual CREATIVE_PACKET v1.1.0 and PRE-ART engine feasibility
Inputs: approved director + model + source files, actual runtime contract schemas.
Outputs: CREATIVE_PACKET.json with correct v1.1.0 schema and computed SHA-256 for every linked source file, a real P06 PerformanceCommand plan if supported by the current code, PREART_REPORT.json, ART_DEMAND_DAG.json, CAPABILITY_MATRIX.json, exact missing-art / alternative-cel requests.
Execute using ACTUAL project tools (CLI may change with code version):
- node engine/tools/creative_handoff.mjs validate --packet <path>
- node engine/tools/creative_handoff.mjs preflight --packet <path>
- node engine/tools/creative_handoff.mjs export-feedback --film <film_id> --packet <path> --out <feedback.json>
- P06 performance-closure command per verified current engine README/handoff, not a guessed CLI.
Gate: all creatively required operations either map to reachable actual render consumers with evidence or emit typed unsupported/missing art; no drawing generated before knowing the required views, hands, underpaint, shadows, contact surfaces, background coverage and frame intervals.
If unsupported, GPT/user chooses whether to commission extra drawings, change the motion route or authorize a creative change. Claude may NOT silently weaken art or direction.

### S5 — Actual image/host/graphics production
ART GPT: verify current installed F01–F80 source-native skill in the new chat including required support docs and witness image availability. A remembered style summary is NOT the skill. Produce original coherent characters/environments, not unlicensed recreations of protected art.
Art order: approved style/mood/identity concept → canonical character master → approved multi-view structural family as needed → separate painted parts and hidden underpaint → eyes/brows/mouth/hand/face/pose/cel transitions → prop/world planes, overscan, masks and clean backgrounds → registered derivative provenance and dimensions.
For every required asset, keep: unique art_job_id, source creative/shot/action IDs, base master SHA, intended views and state interval, actual RGBA/SVG byte hash, crop/alpha, pixel landmark sidecar, reviewer decision, near/far hand layer, deformations and allowed motion routes. Never invent separated transparent bodyparts by simply cropping a flattened illustration.
**Registration is not appearance:** approve rest recomposition, silhouette, seams, anatomy, multi-view identity, shading/lighting, expression and "whole look" before animation.
3D HOST: separate original reusable Blender mesh/rig/face with source .blend, movement/turn/speak test, calibrated perspective/light/ground/depth/occlusion passes and independent approved character identity. A 2D painted host image does not become an editable 3D character.
DECODER: independent mathematical variable graph, units, source mode, render operators, cues; formulas drive actual visuals and pass a change-input → change-graph negative.
Gate: user approves original visual artistry AND all required source-attached states. No model-generated stand-ins as final art.

### S6 — Post-art rig fitting, motion compilation and exhaustive checks
Inputs: actual approved art bytes + reviewed landmarks + approved command demands.
Outputs: measured rig/pose map per unique actor; permitted deformation envelope; authored/approved cels; verified object socket/palm/finger occlusion; POSTART_REPORT; actual Neutrino action plan.
Motion route selected per demand: painted-part rig/IK; bounded approved deform+secondary; alternate illustrated cel/view; real Blender; independent mathematical diagram.
At EACH required frame, validate known rig/contact, state-edge, possession, foot/weight, occlusion, view/cel, frame coverage, painted overlap and owner-specific effect where applicable. A 0-frame check does not equal PASS. Require actual human continuous playback for beautiful timing and acting.
Contact: onset, shared overlap, ownership transfer, held interval and release all must retain physical and painted logic. Different characters reuse command semantics with distinct geometry/style profiles, not generic limb art.
Gate: feasible on REAL approved artwork; impossible gesture → precise new art state/job or typed developer error; never deform valid anatomy beyond approved shape envelope.

### S7 — Animate real film shots on synchronized specialized renderers
2D: Neutrino/Chrome moves the original actual approved image layers and cels with character-specific performance (anticipation, gaze, blink, mouth, body weight, contact and follow-through).
3D: genuine approved Blender host/other 3D elements use the same absolute film frames; output numbered RGBA, depth/occluder, shadow/matte and matching color/camera passes.
STRATEGY: source-model-linked SVG/DOM/Neutrino/motion-graphic frames actually change when inputs change; typography, labels, material and transitions readable at real speed.
AUDIO: actual voices with measured time alignment, cue events, ambiance, music, SFX and intentional silence. Verify decoded final MP4 audio/video from exact current revision. Scratch voice is acceptable for early animatic, not for final-release qualification.
Compositor: exact film frame chooses all layers, camera, effects and audio; every pass has hash, source, owner and depth ordering; no hidden old cache.
Gate: 13s E01 interval = 780 frame-addressed images, 1920×1080 60fps, consistent source revision; no unapproved placeholders. 3D and decoder do NOT have to be forced inside the first 13s if storytelling suffers; they receive separate actual film proofs.

### S8 — Inspect, repair and approve real moving footage
Required inspection: actual native-size video and audible dialogue, not still contact sheet alone. Review story comprehension, emotion, pacing, identity, whole-look, body dynamics, hands, fingers, shadows, environment, camera, actual owner visual changes and synchronized audio. Check automatic owner/isolation negatives and every legally required frame/phase where machine-checkable.
Find earliest PRODUCER responsible: screenplay/direction, missing art/view/cel, source generator, rig/registration, performance adapter, scene graph, compositor, audio, or editor. Fix that producer; do not patch one film frame and claim reusable learning.
Approval requires actual user decision scoped to exact code/art/video SHA. Failed shot → repair, targeted negative + affected render; do not rerender entire film for one unchanged shot.
Output REAL_FOOTAGE_LEDGER.csv includes absolute frames, source SHA, art SHA, audio SHA, motion SHA, final clip checksum, duration, stage, owner, actual review and cost.

### S9 — Scale from real clips to the entire film
E01 qualification: **proposed full opening 32.5s = 1,950 frames**, first extract **[180,960)** absolute = 13s/780 frames. Extract-local [0,780). All values PROVISIONAL until actual audio/animatic + user director approval.
Critically: first 13s starts MID-FILM at f180, not a new separate creative scene. Preserve the actual state at f180 from full scene/approved pre-roll; validate previous f0–179 setup and downstream f960 continuity.
Separate actual film proof of original Blender host entry around 24.75–32.5 seconds once design and 3D model approved. Separate real strategy decoder when script reaches it.
Next: contiguous **90–120s hybrid** selected from this film, proving 2D acting, freeze/memory, real host entry, strategy decoding and final audio cohesively. Then full story in continuous assembly, reviews after every accepted clip, no filler assembly or fabricated style upgrades.
At 60fps: 8min=28,800 frames; 13min=46,800; 20min=72,000. This changes workload and asset counts, NOT the production standard. Runtime is never automatically stretched to satisfy target length.
Final: audience promise/title/thumbnail, factual/rights clearance, narrative and technical QA, actual recorded voices, final audio, coherent characters, physical acting, no misleading financial evidence, human film review and reproducible source commit. Genuine audience metrics are collected after release only.

## 3. Standard for every NEW GPT / Claude session
**Never use memory alone as the complete handoff.** GitHub exact source files + immutable commit + one EPISODE_STATE.json + newest approved/proposed creative files are the repeatable source of truth.

For NEW GPT STORY/DIRECTION:
- Read Channel Bible entire, Episode State + current SOURCE/DECISION registers + Value Blueprint + latest full script, director source + this SOP. Confirm source versions actually loaded and enumerate unresolved choices.
- Propose artistic decisions. Do NOT fake approval, claim scratch timing measured, choose engine shortcuts or generate final art before preflight.
- Deliver ONLY files changing at this checkpoint plus a DELTA_MANIFEST recording what is retained/changed and why. Return artifacts as .md/.json/.csv, not 2,500 lines of duplicated prose with unstable IDs.

For NEW GPT ART:
- Read current installed F01–F80 skill and all essential actual references; current approved art design/master and exact ArtJobs, actor identity and shot/motion requirements.
- Deliver actual original images/alpha and required derivative states plus provenance/landmark metadata; perform iterative style, anatomy, consistency and whole-frame reviews. Do NOT substitute a generic remembered cartoon style or claim to generate an image by writing prompts alone.
- Preserve approval states; new derived art must match actual approved master without forcing generic rig shape.

For NEW CLAUDE CODE:
- Inspect repo root/branch/status/remote/source SHA, local changes and outstanding tasks BEFORE checkout/merge. Preserve work and evidence. Read CLAUDE.md, HANDOFF.md, this SOP, current Episode State, P06 contracts and current approved creative packet.
- Run the real supported CLI, not a guessed tool, and report actual generated files/error codes. Do work that does not require user-owned art. Push only after tested source stability. Never silently use stale V0.3 if newer V0.4 is proposed.
- Reuse same command library for unlike characters; qualified software code is distinct from real-image quality certification.

### How to build a handoff/source pack without 2,500 lines of repeat narration
A session pack is a **reproducible snapshot**, not a fresh bespoke mega-spec.
Include: (1) Channel Bible and SOP by exact version/hash; (2) episode snapshot/state and user-approved decision register; (3) all NEWEST relevant full creative files and relevant earlier locked models; (4) 12-part Experience Director and shot/action/art/continuity manifests; (5) actual runtime schema and producer mapping appropriate to stage; (6) explicit 'do / do not / next gate' instruction; (7) source SHA/file SHA manifest.
Never omit referenced full creative documents merely because a short summary sounds complete. Never include private signer keys, licensed native visual witnesses or personal transcripts in a public source pack.
When only one dialogue line changes, update impacted timing and downstream art/audio/animation by dependency IDs; do not regenerate approved unrelated artwork or rewrite the Channel Bible.

## 4. Strict per-artifact handoff metadata and automated quality gates
Every packet includes: episode_id, revision, approval_scope/status, authoritative_branch, source_commit_sha, source_files[relative_path,sha256,role], upstream_decision_ids, absolute start/end film frames if scoped, manifest schema version, unresolved decisions, blocked reasons, required next owner/action.
Review requires **actual file existence and content hashes**, not a file path invented in chat. A document may be internally consistent without being engine-valid or aesthetically qualified.
Twenty required artistic/technical release obligations live in PRODUCTION_QUALITY_GATE_REGISTRY.json:
G01 story_truth; G02 viewer_story; G03 creative_runtime_mapping; G04 preart_state_closure; G05 f_methods_image; G06 canonical_identity; G07 image_ingest; G08 registration; G09 motion_feasibility; G10 acting_motion; G11 painted_grip_release; G12 view_cel_deform; G13 camera_world; G14 host_3d; G15 strategy_decoder; G16 owner_attribution; G17 final_audio; G18 editorial_final; G19 source_revision; G20 film_progress.
No green PASS for an unspecified check, whole-frame motion where owner stands still, engine static test without real art, or fake signed creative approval. If normative requirements are not yet wired to runtime, record NOT_IMPLEMENTED_ENFORCER and ask engineering to implement the check. Human beauty/comprehension decisions cannot be auto-proved by code.
Technical failures must name producing function, actual wrong behavior, negative reproducer, exact change, transfer scope and why the verified source revision is safe.

## 5. Operate with checkpoints; avoid repeated expensive regressions
- Snapshot source and scope, define test targets before code modifications.
- Targeted unit/negative/short real-owner render after each affected producer change.
- One full end-to-end regression on FROZEN FINAL code SHA before engineering release; do not run two overlapping full suites competing for CPU or rerun obsolete versions merely because the revision name changed.
- A complete regression confirms code behavior only, not cinematic quality.
- Real film evidence must be produced separately with actual approved assets and exact sound.
- Store remaining work in EPISODE_STATE.json and HANDOFF.md; every interruption can restart from it. **Never promise background completion without an actual scheduled task.**
- Record process efficiency: hours to accepted film second, number of art rerolls/repairs, root-cause recurrences, actual costs and failed criteria. Never optimize raw rendered frame counts while the film remains unwatchable.

## 7. Definition of a scalable, high-quality production system
**Reusable:** creative-value research procedure; 12-part direction grammar; action semantics and actor-specific performance profiles; art-demand closure; art-master/derived-state process; registration; 2D/3D/graphics/audio adapters; quality tests; ledger and repair learning.
**Episode-specific by design:** original plot, humor, humans, moral choices, claims and calculations, art geometry, camera choices, dialogue, scene timing and authentic identities. Do not make every episode look like Mia or automate emotional writing with a fixed formula.
**Never promised:** a flawless render for every possible script, effortless generation of every art state, guaranteed virality or automatic code-based certification of beauty. Instead, implement explicit support/refusal, source-grounded review and reusable repairs that close failure classes while preserving artistic ambition.

# THE BETTER ONE — NON-NEGOTIABLE PRODUCTION EXECUTION STANDARD V2
**Status:** Normative engineering + artistic acceptance contract. **Authority:** the user's 24 Nov 2026 channel Bible is editorial source of truth; this spec translates it into observable production obligations. It does NOT declare existing P05 capabilities tested or approve any image/story. **Use only with** the actual P05 v1.1.0 creative packet and engine schemas. Existing approved creative facts, statements and visuals may never be silently rewritten by code.

**Critical motivation:** Registration proves WHERE independent painted parts are positioned. It cannot prove those parts look like the SAME character, bend attractively, perform the required ACTION, show correct acting, remain convincing between keyframes, or integrate the 3D host. The system must prove **creative intent → sufficient painted states → real rig → executable acting → frame-visible consequence → final motion aesthetics**.

## III. Decision logic: use the correct visual technology, not a favorite tool

**Route per SHOT OPERATION**, not per whole episode. Each meaningful operation gets \`action_id, effect_owner, visual_mode, registered_inputs, output_passes, expected_consequence, frame_window, route_rejection_reason\`.

1. **RIGID_2D:** approved unchanged painted object translation/rotation/scale where geometry remains visually valid.
2. **PART_RIG_2D:** actual separated, underpainted and registered images; stable pivots; FK/IK and constrained interaction; body support.
3. **APPROVED_CELS:** view/pose/hand/expression state switches plus approved inbetweens, shared anchors and occlusion ordering.
4. **APPROVED_DEFORM:** alpha-correct registered mesh/path deform with non-overlap and topological integrity, bounded so painterly/shaded contour stays approved.
5. **SEMANTIC_GRAPHICS:** real variable-derived symbols, diagrams, words and visual metaphors; actual numeric model is authority.
6. **BLENDER_3D:** real mesh/rig/face performance where actual depth, rotations, contact or host acting requires 3D; synchronized RGBA/depth/object matte/shadow passes.
7. **WORLD_CAMERA_TRANSITION:** fully painted worlds, calibrated depth planes and moving camera with actual overscan/occlusion and continuity.
8. **APPROVED_SPECIAL_VIDEO:** optional paid shot-specific generated video only after a real need, quote and explicit approval; flattening loses fine-grained editability and does not replace the registered character rig.

**Hard refusals:** moving a flattened image ≠ articulated acting. Rotating a flat face ≠ real head turn. Free 3D host orbit from one illustration ≠ modeled 3D. A transform interpolation ≠ deformation. A crossfade ≠ valid physically motivated state transition. An icon moving ≠ truthful computation. A layer merely overlapping ≠ believable grip.

**Tool selection:** preserve P05 Neutrino/Chrome for existing 2D and SVG/graphics operations; do not rebuild another full character engine from scratch. Blender is a separate genuine rigged host producer. Live2D/Moho/Cartoon Animator/Spine are valid fallback/proven design references only if tested on Mia's REAL approved art against visual quality, controllability, labor cost and integration, never declared installed or automatically compatible.

## IV. Source-grounded character/art construction — no "beautiful static puppet"

### IV.A Before generation: motion-first demand, not geometry-first art

For each actual film character/prop and its actions:
- Canonical identity \`identity_id\`, approved master and recurring features that cannot drift.
- Actual phase graph and expected audience-readable acting: gaze, anticipation, contact, weight, hold, follow-through, expression and exit.
- Each separable visual role (head, neck/torso, pelvis/limbs/hands, coat/hair, props; species/shape-specific, not hardcoded human arms).
- Every **needed** pose, camera view, expression, eye/blink, mouth/viseme, HAND/open/closed/grip, material/light and near/far occlusion state.
- Hidden surfaces and underpaint revealed by motion: behind arms, head, clothes, body, prop, world and masks.
- Needed localized deform/cel transitions and painted inbetweens if a rigid part rotation is visually wrong.
- Minimum painted world coverage and source resolution at every camera extreme.
- ArtJob DAG: master → approved identity → source-attached part/state edits → masks/underpaint → world/mechanism → transitions, with consuming action/frame ranges.
- Each ArtJob's F01–F80 applicability list plus actual source observations, molecular construction clauses, witness images/hashes and expected visual evidence. No generic "Kurzgesagt style" prompt or guaranteed fidelity by merely citing F-numbers.

**Pre-art ENGINE validation** checks operation support and demand closure; it CANNOT certify pixel-space reach before art exists. Impossible or unsupported actions get exact feedback to GPT/human without changing artistic intent.

### IV.B Generate actual image assets with ChatGPT + installed F01–F80 skill

- Verify current skill files and native visual witnesses are accessible in the new ChatGPT art context. A GitHub markdown filename or assistant memory is not a valid witness.
- Approve gorgeous canonical character/world masters with the **entire whole look**: silhouette, head/body/face, anatomy, palette roles, material, shading and edges, accessories, lighting and scene detail. Reject masters that rely on generic tube-limbs or unattractive static anatomy.
- Derive EVERY demanded part/state from approved canonical masters through references/edits; do not independently generate unanchored "same Mia" pictures.
- Distinguish a full approved character illustration, which is concept/identity master, from transparent animation-ready physical assets.
- For each sprite: actual alpha and crop, correct edge/matte, overlap or underpaint, unambiguous role, valid view and state. If art model fails transparency/hidden detail, request corrected derivation; do not have the runtime invent painted anatomy.
- Image consistency review: composite correct states on original master; compare identity shapes, joint seams, palette/shadow and accessories at view transitions, especially face/palm and elbow/cuff.
- Only approved real PNG/SVG image bytes, content SHA and human art approval can enter G4. Operator-attested generated-image origin is honestly labelled; do not fake provider cryptographic verification.

### IV.C Test case for a REAL acting scene (not a diagnostic stand-in)

Mia in restaurant reacts to confusing bad news, reaches toward a real object, closes the painted hand, holds and moves it, changes gaze and expression, releases, then recovers. For each meaningful point:
- **Rest:** head/torso/arm paint and costume seams aligned, no doubled parts, consistent identity.
- **Anticipation:** eyes/shoulder/hips lead the intended motion, no random breathing replacing acting.
- **Reach:** shoulder→elbow→wrist→palm chain maintains length and plausible 2D silhouette in actual art.
- **Contact:** correct palm normal and gripped surface, fingers in front/behind prop correctly, correct touch point.
- **Hold:** hand closure and contact painted correctly on **every contracted frame**, including blur and camera movement.
- **Release:** possession ends, hand opening/separation and object trajectory coherent; no floating/attached prop.
- **Reaction:** real facial drawing, gaze and head view; no identity-switching profile, unapproved flip or emotive default.
- **Secondary:** sleeves/hair/cloth/shadows settle appropriately, no decorative random movement.
- **Cut/next shot:** state continues or explicit motivated transition; no hand/prop teleport.

A correct matrix transform with a broken elbow/shadow must fail **visual acting review** even if all technical residuals passed.

## V. Actual artwork-first rig registration and physical motion

### V.A Registration (NECESSARY; NOT SUFFICIENT)

- Preserve unmodified approved source art and its hash; compute pixel bbox, intended alpha bounds, masks and crop-local coordinate.
- Landmarks are **reviewed on real pixels**; explicitly tag source-pixel vs part-local vs canonical-master vs rig/world/screen spaces.
- Solve allowed transforms from valid nondegenerate correspondences; reject mirror, bad scale, excessive skew and unstable residual.
- Draw rest-pose original master vs recomposition overlay and test for seam/holes/overpaint/identity shift. A numerical residual alone cannot prove a good seam.
- Register visible and hidden surfaces, occlusion topology, front/rear paint order and actual contact patch; state-channel images require their own lineage.
- Fit measured pivots/joint lengths/constraints to the art, not the reverse; don't stretch approved anatomy to make preselected coordinates work.

### V.B Frame execution order

For each actual required frame and subframe:
1. Resolve shot, film clock, actual source art hashes, direction and actor IDs.
2. Resolve canonical state timeline with independent pose/view/EYES/MOUTH/EXPRESSION/HAND/material/lighting/occlusion and possession.
3. Evaluate intended directed primary motion; verify every authored semantic action has an actual motion producer and not a metadata-only label.
4. Add approved acting with meaningful anticipations, eyes/gaze, breathing, head and joint lag, secondary/settling subject to contact/limits. Validate parameters/timing.
5. Apply support, FK/IK, joint/limb constraints, palm normal/prop socket, object and linked mechanism reaction. No unchecked grip, silent failed constraint or exception swallowing.
6. Resolve correct approved cels, view turn, morph/deform, masks/occluders, foot/shadow receiver and hidden paint.
7. Apply camera once, correct parent and world transforms, validate entire painted camera footprint.
8. Actually execute Neutrino timeline/row in Chrome on approved image layers; decode real pixels.
9. Check each required action's real visible **owner**, state transition and requested visual consequence; changing camera/background alone cannot pass it.
10. Record frame/source/owner hashes and exception count. A required frame not evaluated = failed stage, not "not applicable".

### V.C Quality must be checked IN MOTION

Technical gates: no NaNs/invalid topology/IK residual, no missing image, no dislocated contact, no blank world, no stale frame, all requested owner motion visible, correct audio and numbers.

Artistic gates: cohesive identity and expression across motion, believable weight, appealing arcs, natural anticipation/holds/recovery, clean elbow/shoulder silhouette and hands, correct light/shadow/contact, clear comedic and emotional timing, shot focus.

**Native-resolution rendered moving footage**, including extreme frames and transitions, must be judged. A contact sheet and all-green pixel QA is insufficient.

### V.D Generalization

Implement the reusable *failure class*, not a literal Mia coordinate or exception. Test on unfamiliar character topology and different prop position. Do not prohibit shot-specific creative direction or shot-specific correctly approved animation keys—only prohibit hacks in reusable engine producers.

If a required physical act cannot be supported:
- FIRST determine whether the engine math/connection is wrong; if so repair it generally.
- Else request missing approved source-attached part/cel/underpaint/angle.
- Else provide bounded frame/pose/restaging alternatives to GPT + human for approval.
- Else block that action; no fallback generic art, static slide or undeclared generated clip.

## VI. The 3D host — real character, not a pasted illustration

- Original character concept, personality and proportions approved; design must work from front/side/back, not be one image.
- Actual Blender mesh, correct topology/UV/materials, armature, skin weights, facial shape keys and tested performances (walk/idle/reaction/gaze/point/talk/exit).
- Include original .blend or qualified editable master; procedural low-poly placeholder cannot be declared production-quality.
- Frame-accurate Blender camera and compositor view calibration (projection, world origin, scale, lens, near/far, shared proxy floor and contact anchors).
- At every compositor frame, require RGBA host image plus depth/object matte and ground-contact or cast-shadow pass as needed. Correct premultiplication, edge treatment, color management and motion blur.
- Real host–2D contact: calibrated feet on floor, hands/gaze on props, appropriate body occlusion behind 2D tables and foreground patrons, shadow direction matching room.
- Unit test with actual mixed frames and negative: shift host camera 10%/remove shadow/remove occluder -> pipeline rejects; human judges integration in running footage.
- If model creation isn't solved, \`HOST_3D_ASSET_PENDING\`, not fake flat cutout. The 2.5D compromise only with explicit launch creative approval.

## VII. Strategy decoder and truth-calibrated motion graphics

- GPT supplies verified claims; separate real sources, dramatization, hypothetical numeric assumptions and model-derived results (Bible F/R/M/H/X modes).
- Canonical model card: variable IDs, units, baseline, source status, formula, constraints, choice levers, sensitivities, adversarial conditions, uncertainty.
- The renderer receives actual computed value/time series: **edit one input → recompute values → source-linked labels/visual flow/graphs change**. Prohibit ad hoc "93% success" without calibrated evidence.
- For Mia, compare contribution after variable costs and constrained capacity, not revenue volume alone. Customer demand, service quality, waste, overhead, add-on effort and model caveats remain explicit.
- Strategy space visually transforms **planted physical story objects** into variables and causal chains; host explains as a curious fallible participant rather than victorious guru.
- Motion graphic readability: one relationship at a time, stable units/scale, source labels and intentional visual holds. No unreadable dashboard or flashy invented data.
- Negatives: change cost but freeze graph; hide capacity; reverse sign; misleading chart baseline; remove rival/customer response. All must reject or be explicitly labeled an illustrative simplification.
- Truth model is separately reproducible from the final motion timeline. A beautiful graph is not proof of good strategy.

## X. Production efficiency — no fake progress

- Reuse **rigging algorithms, performance verbs, face/hand-control conventions, camera/transition shaders and sound/graphics primitives**, not identical unique character identities in unrelated stories. The recurring HOST is the legitimate reused character; Mia remains episode-specific.
- Do not overfit hardware or art skill to one shot. Repair system producers at the earliest wrong source and leave a reusable negative test.
- Run targeted bounded regressions + a clean final P05 qualification once; don't spend the new Claude account reproducing endless 120-second fixture films.
- Diagnose render/GPU bottleneck using measured accepted film seconds per GPU minute and wall-clock, not assuming a rented GPU changes Claude model usage or removes art work.
- Optional video-generation purchase requires request-specific quote, reference suitability, expected reroll rate and approval. Code-backed edits remain favored for repeatable acting.
- Keep parallel work independent: GPT research/script, Claude core engineering tests, exploratory art-look concepts can proceed; dependent final cels/rigs wait for approved direction/pre-art and master approval.

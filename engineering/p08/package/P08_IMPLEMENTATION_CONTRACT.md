## B. Physical motion and constraints (B01–B09)

**B01. Real prop driver and transform authority.** Inspect new P07 `prop_support.mjs`, schema, `temporal.mjs`, `performance_qa.mjs`. Its report proves surface producer but does not prove hand-derived object transform. Explicit mode per span: `ACTOR_DRIVEN` (approved hand/palm world transform drives rigid prop), `OBJECT_DRIVEN` (directed prop path drives object; hand follows via IK; hand is supporter, not claimed transform writer), `SURFACE_DRIVEN` (fixed or moving registered surface transform), `FREE_AUTHORED` (directed free motion, zero grip supports only where allowed). Exactly one transform writer per frame, independent support set. For actor-driven hold define measured `T_hand_socket_to_prop` from approved contact alignment (or captured at verified transfer boundary). With homogeneous transforms in same world space:
```
P_world(f) = H_world(f) * H_to_P
H_to_P = inverse(H_world(t-1)) * P_world(t-1)  // transfer preserves pose; compute once from exact validated previous frame
```
Here `H_world` includes hand contact basis/scale; use rigid compatible transform, not arbitrary nonuniform scaling; prop orientation is constrained. Compute driver hand via primary pose/IK to independent directed world target; compute prop; solve secondary supporters against prop; re-evaluate all constraints. No circular hand→prop→same driving hand solve. Topological dependency graph per frame; cyclic dependency refuses or uses explicit coupled solver with residual evidence (no silent iteration). Surface uses registered normal/tangent and relative transform. `OBJECT_DRIVEN` is valid for choreography but must be named, never mislabeled hand authority. Prop path conflicting with hand/surface driver fails. At transfer t, incoming valid t−1, outgoing valid until transfer, continuity residual of position and angle, explicit subsequent velocity/acceleration intent; no snap. Do not reuse previous *evaluation order* mutable state; precompute immutable transfer/bake or deterministic seek. Every-frame support checks including near/far art and release only specified hand. Tests move primary hand without changing any prop keys: actual prop owner pixels must move accordingly; reverse on object-driven case; delete driver transform consumer while retaining supporter metadata; should fail. ## Acceptance rule

The accompanying `P08_REQUIREMENT_MATRIX.json` is the mandatory checklist. All 38 requirement IDs must have result rows (not all can be declared real-qualified before actual input). `CODE_VERIFIED_AWAITING_REAL_INPUT` means genuine implementation and positive/negative execution, with named external data still missing. `BLOCKED_IMPLEMENTATION` means code not complete, even if refusal works. `ACCEPTED_REAL` requires actual human approval. No statement that all future bugs are impossible. Goal: every known failure represented by a real producer or invariant, a real consumer and a discriminating negative test; unknown/new artwork problems return to earliest producer and cannot silently receive film approval. Preserve creative authority and do not trade artistic quality for a green test count.
